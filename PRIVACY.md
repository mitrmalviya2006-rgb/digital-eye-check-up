# Questionnaire privacy behavior

Questionnaire answers and the in-progress C1 result remain in the Component 16 in-memory session service; they are not persisted. The final C12 result and minimal consent receipt are saved to IndexedDB only if the user opts in at C1. Refreshing, closing the tab, or resetting the session discards questionnaire and temporary session data. No cookies, localStorage, cloud backend, or synchronization are used by the data layer.

Component 3 adds a separate, explicit assent before loading MediaPipe. It downloads the runtime/WASM from jsDelivr and the face model from Google Cloud Storage. Face frames and landmarks are processed locally and are not sent to those hosts. MediaPipe's current privacy notice says the SDK sends performance and usage metrics to Google; the Component 3 disclosure identifies that behavior before analysis starts. No positioning or face data is persisted by this application.

Component 4 asks for explicit assent before deriving eye/iris geometry from the already-running local face landmarks. The landmarks and derived geometry stay in page memory and are not uploaded or persisted. Withdrawing eye-localization assent clears the current eye result and stops the shared detector until the user agrees and retries; it does not ask for camera permission again. The model provides iris boundaries but no separate pupil, per-eye confidence, visibility, or occlusion score. See [EYE-LOCALIZATION.md](./EYE-LOCALIZATION.md).

Component 5 asks for separate assent before reading live-preview pixels for technical quality checks. It samples the same video element already used by Components 2–4, at a throttled rate and reduced resolution. The temporary canvas/pixel buffer is cleared when assent is withdrawn or the step is stopped/unmounted; frames and metrics are not uploaded, saved to disk, or logged. It does not open another stream or run another detector. Component 4 currently cannot supply per-eye confidence or visibility/occlusion evidence, so Component 5 reports those checks as unavailable and keeps `valid` false even when measurable image properties pass; this limitation is described in [QUALITY.md](./QUALITY.md).

Component 6 asks for a separate, explicit assent before automatically extracting a full-resolution PNG from the same live video element. The PNG Blob and a temporary reduced pixel buffer exist only in page memory; validation canvases are cleared after each attempt and again during teardown. Consent withdrawal invalidates any in-flight frame before it can be emitted. Successful frames are exposed only through the local Component 7 handoff events and are discarded when screening stops or the page closes; nothing is uploaded or persisted. Automatic capture remains disabled while the required Component 5 result is invalid. See [CAPTURE.md](./CAPTURE.md).

Component 7 receives only the validated Component 6 capture batch. It decodes each PNG once, extracts OD and OS crops locally, releases each decoded bitmap and temporary canvas after use, and emits typed pixel arrays in memory for Component 8. It does not upload or persist the original capture; stopping or cancelling releases its retained references, and image/tensor values are not logged. See [PREPROCESSING.md](./PREPROCESSING.md).

Component 8 reuses Component 7's in-memory pixel arrays and transformed iris landmarks; it does not decode or upload images, log biometric measurements, or write feature vectors to persistent storage. Stopping or leaving the page releases retained feature data. The current detector supplies neither pupil boundaries nor per-eye confidence, so Component 8 marks those measurements unavailable instead of estimating them. See [FEATURE-EXTRACTION.md](./FEATURE-EXTRACTION.md).

Component 9 has no configured trained model or inference runtime. Its default state reports model unavailability without running inference or producing SPH/CYL/Axis or confidence values. The future adapter contract accepts only an explicitly local runtime and keeps features in memory; it does not permit a third-party AI endpoint. Stopping the prediction step aborts in-flight work, discards the feature-batch reference, and disposes the model session. See [PREDICTION.md](./PREDICTION.md).

Component 10 only organizes the C9 in-memory prediction result. It does not retain or log eye images and makes no network requests. The eye-separated result is released when screening stops or the step is unmounted; nothing is written to browser storage or sent to a service. See [EYE-ANALYSIS.md](./EYE-ANALYSIS.md).

Component 11 receives only Component 10's eye-separated estimates plus a compact quality/stability summary carried from Component 6. The summary contains no images, pixels, or feature vectors. Results and reason codes remain in page memory and are released when screening stops; no data is uploaded or persisted. See [VALIDITY.md](./VALIDITY.md).

Component 12 displays only values authorized by Component 11's explicit presentation gate. C12 sends the final result to Component 16; local history persistence occurs only after the optional C1 history opt-in. Component 13 attempts are retained in an image-free form. Component 15 reads C12/C14 records locally without recalculation. See [DATA-PRIVACY.md](./DATA-PRIVACY.md) for the shared storage boundary, controls, and browser limits.
